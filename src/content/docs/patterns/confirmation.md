## 概要

- 元に戻せない操作と影響の大きい操作の前に、確認ダイアログを表示する。
- このページでは、確認を出す操作の範囲と、確認ダイアログに書く内容を決める。
- 部品の使い方（props など）は、NgiAlertDialog のページを参照。

## いつ使うか

### 確認を出す操作

| 操作 | 例 |
| --- | --- |
| 削除 | 船舶、ユーザー、書類、写真の削除 |
| 上書き | マスタの上書き保存、テンプレートの適用 |
| 取り消し | 依頼の取り消し、配船の解除 |
| 一括操作 | 複数件の削除、複数件のステータスの変更 |
| ステータスの変更 | 計画中から予定への変更、アーカイブ |
| ほかの人に届く送信 | 確認依頼、承認依頼、文書の共有 |

### 確認を出さない操作

| 場面 | 代わりに使うもの |
| --- | --- |
| 操作の結果を知らせるだけの場合 | トースト（NgiToaster） |
| 入力欄を含む操作の場合 | ダイアログ（NgiDialog）か、専用のページ |
| 選択肢が 3 つ以上ある場合 | ダイアログ（NgiDialog） |

- 「元に戻す」の機能で、確認の代わりにすることは、当面は行わない。
  - 「元に戻す」を持つ部品がないため。
- 未保存の変更を破棄するときの確認は、「保存・戻る・中断」のページを参照。
  - 確認ダイアログの書き方は、このページの決まりに従う。
- 安全や運航に関わる操作（QA の 1-7）の確認は、当面は対象外とする。
  - 該当する操作の有無を確かめてから決める。

## 決まり

### 部品

- **PAT-CONFIRM-01（必須）** 確認ダイアログには、NgiAlertDialog を使う。
- **PAT-CONFIRM-02（必須）** ブラウザーの `confirm()` を使わない。
- **PAT-CONFIRM-03（必須）** 確認ダイアログの上に、別の確認ダイアログを重ねて開かない。

### タイトル

- **PAT-CONFIRM-04（必須）** タイトルは「{対象}を{操作}しますか？」の形で書く。
  - 対象には、「船舶」「書類」のように、操作する物の種類を書く。
  - 末尾には、全角の「？」を付ける。
- **PAT-CONFIRM-05（必須）** 「確認」「削除確認」「警告」のような、何が起きるかが分からないタイトルにしない。
- **PAT-CONFIRM-06（必須）** 「削除しますか？」「本当に削除しますか？」のように、対象を省いたタイトルにしない。

### 説明文

- **PAT-CONFIRM-07（必須）** 説明文には、操作すると何が起きるかを書く。
  - 対象の名前が分かる場合は、「{名前}」を含める。
- **PAT-CONFIRM-08（必須）** 元に戻せない操作の場合は、説明文の最後に「この操作は元に戻せません。」と書く。
- **PAT-CONFIRM-09（必須）** 複数の対象を操作する場合は、対象の名前を箇条書きで示す。
  - 6 件以上の場合は、5 件まで示し、6 件目からは「ほか {N} 件」とまとめる。
  - 箇条書きは、NgiAlertDialog の `children` に入れる。

### ボタン

- **PAT-CONFIRM-10（必須）** 実行ボタンの文言は、操作の名前を体言止めで書く。（例：「削除」「解除」「適用」）
  - 目的語が必要な場合は、「権限を追加」の形で書く。
  - 「OK」「はい」「実行」は使わない。
- **PAT-CONFIRM-11（必須）** キャンセルボタンの文言は、「キャンセル」とする。
- **PAT-CONFIRM-12（必須）** データが失われる操作（削除・上書き・破棄）の実行ボタンは、solid × danger にする。
- **PAT-CONFIRM-13（必須）** データが失われない操作の実行ボタンは、solid × primary にする。
  - 元に戻せない送信（確認依頼など）も、データは失われないので primary にする。
- **PAT-CONFIRM-14（必須）** キャンセルボタンは、outline × neutral にする。
- **PAT-CONFIRM-15（推奨）** 画面の上で削除を始めるボタン（確認ダイアログを開くボタン）は、outline × danger にする。
  - 画面の solid × primary のボタンと並んでも、主要な操作に見えないようにするため。

### 実行中と失敗

- **PAT-CONFIRM-16（必須）** 実行ボタンを押したあと、処理が終わるまでは、実行ボタンを loading の状態にする。
- **PAT-CONFIRM-17（必須）** 処理が終わるまでは、確認ダイアログを閉じない。
- **PAT-CONFIRM-18（必須）** 処理が失敗した場合は、確認ダイアログを閉じずに、ダイアログの中にエラーを表示する。
  - エラーの書き方は、ライティングの「メッセージ」のページを参照。

:::note[部品の課題]
- NgiAlertDialog には、PAT-CONFIRM-16〜18 の動作（実行中の表示、完了まで閉じない動作、ダイアログの中のエラー）が用意されていない。
- 今は、各アプリが独自の ConfirmDialog で実装している。
- 部品に追加するまでは、NgiAlertDialog の `open` と `onOpenChange` で開閉を制御して実装する。
:::

## 文例

次の文例は、対象の名前を置き換えて使う。

| 操作 | タイトル | 説明文 | 実行ボタン | 実行ボタンの色 |
| --- | --- | --- | --- | --- |
| 1 件の削除 | 船舶を削除しますか？ | 「{船名}」を削除します。この操作は元に戻せません。 | 削除 | danger |
| 複数件の削除 | {N} 件の書類を削除しますか？ | 次の書類を削除します。この操作は元に戻せません。<br>（書類の名前の箇条書き） | 削除 | danger |
| 上書き | テンプレートを適用しますか？ | 「{テンプレート名}」の内容で、現在の設定を上書きします。この操作は元に戻せません。 | 適用 | danger |
| 取り消し | 配船を解除しますか？ | {オーダー}の配船を解除します。 | 解除 | primary |
| ステータスの変更 | 船舶をアーカイブしますか？ | アーカイブすると、オーダー登録時の選択候補に表示されなくなります。 | アーカイブ | primary |
| ほかの人に届く送信 | 確認依頼を送信しますか？ | {宛先}に確認依頼を送信します。この操作は元に戻せません。 | 送信 | primary |

- 説明文は、1 文目に何が起きるかを書き、2 文目に元に戻せるかどうかを書く。
- 元に戻せる操作では、「この操作は元に戻せません。」を書かない。

## 良い例と悪い例

| 悪い例 | 理由 | 良い例 |
| --- | --- | --- |
| タイトル「削除確認」 | 何を削除するのかが分からない | タイトル「タグを削除しますか？」 |
| タイトル「削除しますか？」 | 対象が書かれていない | タイトル「免状を削除しますか？」 |
| 実行ボタン「OK」「はい」 | 押すと何が起きるかが、ボタンから分からない | 実行ボタン「削除」 |
| 削除の実行ボタンが primary | 元に戻せない操作だと、見た目から分からない | 削除の実行ボタンを danger にする |
| 元に戻せる操作の実行ボタンが danger | 必要以上に危険に見え、利用者が操作をためらう | 実行ボタンを primary にする |
| `confirm()` で「「{名前}」を削除します。よろしいですか？」と表示する | 見た目と文言をそろえられず、ボタンの文言も変えられない | NgiAlertDialog で表示する |
